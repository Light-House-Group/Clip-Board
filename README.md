# Clip-Board

> A privacy-first clipboard history manager for macOS. Encrypted at rest. Zero network code. Zero telemetry.

[![Platform: macOS 14+](https://img.shields.io/badge/Platform-macOS%2014%2B-blue.svg)](https://www.apple.com/macos)
[![Swift](https://img.shields.io/badge/Swift-5.9-orange.svg)](https://swift.org)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Encryption](https://img.shields.io/badge/At--Rest-AES--GCM%20256-brightgreen.svg)](#security--privacy)

Clip-Board is a tiny, native macOS menu-bar app that remembers what you copy and lets you paste it back into the previously focused app with one click — without giving up your privacy.

Most clipboard managers either keep your history in plaintext, sync it to a cloud you don't control, or both. Clip-Board's posture is the inverse: everything stays on-device, encrypted with a key bound to your Mac's Keychain, and the binary has no networking code to leak it anywhere even if it wanted to.

## Features

- **Global hotkey** (configurable, defaults to ⌥V) opens a floating panel anywhere.
- **Menu-bar app** — no Dock icon. Left-click to open the panel, right-click for a context menu.
- **Text and images.** Captures text plus any image on the clipboard (screenshots copied with `⌃` modifiers, images copied from browsers, etc.). Image rows render shrunk to the panel width; hover 1 s for a full-resolution scrollable preview. Click to copy + auto-paste it back.
- **Encrypted at rest** with AES-GCM (256-bit). Key in Keychain, `WhenUnlockedThisDeviceOnly`, non-syncable. **Images are encrypted too** — each stored as its own encrypted file, never embedded in plaintext.
- **Source-app attribution.** Each entry shows the icon and name of the app it was copied from.
- **Auto-paste** synthesizes ⌘V into the previously focused app so you can press the hotkey, click an item, and have it land in the right text field.
- **Multi-select** — right-click → *Select*, then click rows to pick several and delete them in one go.
- **Pinned items** persist beyond the 100-item rolling window for the rest.
- **Full value on hover** — any row whose content is visually truncated opens a smart, scrollable, text-selectable popover after a 1-second hover.
- **Hotkey conflict detection** — the recorder warns when you try to bind to a well-known macOS shortcut (⌘C, ⌘V, ⌘Space, ⌘⇧3, etc.).
- **Respects transient pasteboard markers** — items written by password managers and similar tools with `org.nspasteboard.TransientType`, `ConcealedType`, or `AutoGeneratedType` are never persisted.
- **No network code in the binary** — no `URLSession`, no analytics SDK, no third-party dependencies.
- **Per-item size cap** (~100 K chars for text; 25 MB for images) so a single huge copy doesn't bloat the store.
- **Schema-versioned storage** with quarantine-on-corruption — a bad decrypt is moved aside, never silently dropped.
- **Launch at login** toggle in the menu.
- **Confirmation before clearing** history; ⌥-click clears pinned too.

## Install

### Homebrew (recommended)

```bash
brew install --cask light-house-group/taps/clip-board
```

This adds the `light-house-group/taps` tap once, downloads the signed zip, and installs `Clip Board.app` into `/Applications`. To update later:

```bash
brew update
brew upgrade --cask clip-board
```

To uninstall:

```bash
brew uninstall --cask clip-board
```

### Download the release manually

Grab `Clip-Board.zip` from the [latest release](https://github.com/Light-House-Group/Clip-Board/releases/latest), unzip it, and drag `Clip Board.app` into `/Applications`.

The release binary is **ad-hoc signed**, so on first launch macOS Gatekeeper will say it can't be verified. Right-click the app → **Open** → **Open** to bypass the warning the first time. (If you want notarized builds, see [Build from source](#build-from-source) below — a `DEVELOPER_ID` plus `--notarize` flag is all the release script needs.)

## First run

1. The app launches as a menu-bar item. There is no Dock icon, no main window. Look for the clipboard glyph in your menu bar.
2. **Left-click** the menu-bar icon, or press the default hotkey **⌥V**, to open the history panel.
3. On the first auto-paste attempt, macOS asks for **Accessibility permission** — required to synthesize ⌘V into the previous app. Without it, items still copy to the clipboard; you paste manually with ⌘V.
4. **Right-click** the menu-bar icon to change the hotkey, toggle launch-at-login, or quit.

| Show / hide history | Click menu-bar icon, or press the configured hotkey |
| Copy + auto-paste into previous app | Click a row, or press ⏎ on the selection |

## Security & privacy

### Threat model

| What Clip-Board protects | How |
| :--- | :--- |
| At-rest disclosure of clipboard history (someone reads your disk, a backup, an unsupervised laptop) | AES-GCM-256 encryption of the on-disk file using a key in your Keychain |
| Cross-device leakage | Encryption key marked `kSecAttrSynchronizable = false` — never propagates via iCloud Keychain |
| Capture of sensitive transient data | Honors `org.nspasteboard.TransientType`, `ConcealedType`, and `AutoGeneratedType` — items so marked are skipped, never persisted |
| Silent data loss on corruption | A failed decrypt quarantines the file to `history.broken-<timestamp>` and starts fresh; nothing is destroyed without trace |

### What Clip-Board does **not** protect against

- **An attacker with the same user privileges while the app is running.** They can read the decrypted in-memory history. This is a fundamental constraint of any clipboard manager that gives you the data on demand.
- **Loss of the Keychain key.** Deleting the entry permanently destroys the history. By design — there is no recovery, no escrow, no second copy.
- **Multi-user systems where another local user has root.** Standard threat boundary.

### What's *not* in the binary

- No `URLSession`, no networking framework imports
- No analytics, telemetry, or crash-reporting SDK
- No third-party Swift packages or CocoaPods dependencies
- Only Apple-shipped frameworks: SwiftUI, AppKit, CryptoKit, Security, ServiceManagement, Carbon

You can verify this with `otool -L "Clip Board.app/Contents/MacOS/Clip Board"` after downloading a release.

### Auto-paste and the Accessibility permission

Auto-paste works by synthesizing a ⌘V keystroke into the previously focused app via `CGEvent`. macOS requires the Accessibility permission for synthetic keystrokes. The relevant code path is [`AutoPaster.sendCmdV`](Clip%20Board/History.swift) — a few lines, no surprises. If you deny the permission, items still land on the clipboard and you paste manually.

See [SECURITY.md](SECURITY.md) for the disclosure policy.

## Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                        Clip_BoardApp (@main)                    │
│   NSApplicationDelegateAdaptor → AppDelegate                    │
└─────────────────────────────────────────────────────────────────┘
   │
   ├─ KeyManager            Keychain-backed AES-GCM seal/open
   ├─ PersistenceManager    Encode → encrypt → atomic write
   ├─ ItemsViewModel        Dedupe · trim · pin · debounced save
   ├─ ClipboardWatcher      0.5s NSPasteboard.changeCount poll
   ├─ HotkeyManager         Carbon EventHotKey for global shortcut
   ├─ AutoPaster            NSWorkspace tracking + synthesized ⌘V
   ├─ MenuBarController     NSStatusItem + right-click NSMenu
   ├─ HistoryWindowController  Cached NSPanel + NSHostingView
   └─ HotkeyConflict        Curated catalog of known shortcut clashes
```

The floating panel and the menu-bar window share the same SwiftUI root (`SharedHistoryRootView`). The panel is **prewarmed off-screen at launch** so the first user-visible show is instant — SwiftUI's expensive first render is paid for during startup.

### Data flow

1. You copy text → macOS pasteboard updates → `changeCount` increments.
2. `ClipboardWatcher` polls every 500 ms, detects the change, **skips transient/concealed types**.
3. Trimmed text → `ItemsViewModel.addItem` → dedupe (move-to-top on exact match) or insert.
4. After a 300 ms debounce, the items array is snapshotted on the main thread, then handed to the IO queue: **encode → AES-GCM encrypt → atomic write** to `~/Library/Application Support/ClipboardManager/history.json.enc` (file mode `0600`, directory mode `0700`).
5. On launch: load file → decrypt → decode. If anything fails, **quarantine** to `history.broken-<timestamp>` and start fresh.

History is wrapped as `{"version": 1, "items": [...]}` for forward compatibility. The legacy unversioned format is migrated transparently.

## Build from source

### Requirements

- macOS 14+
- Xcode 15+ (Xcode 26 tested)

### From Xcode

```bash
git clone https://github.com/Light-House-Group/Clip-Board.git
cd Clip-Board
open "Clip Board.xcodeproj"
```

Select the `Clip Board` scheme, then Product → Run.

### From the command line

The repo ships with a release script. The built `.app` lands at the project root:

```bash
./scripts/release.sh                      # ad-hoc signed
DEVELOPER_ID="Developer ID Application: ..." \
  ./scripts/release.sh                    # signed with your Developer ID

NOTARY_PROFILE=clip-board \
  ./scripts/release.sh --notarize         # signed + notarized + stapled
```

The script puts the final `.app` and a `Clip-Board.zip` under `release/`.
