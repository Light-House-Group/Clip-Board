# Clip-Board

A privacy-first macOS clipboard history manager. SwiftUI + AppKit. Encrypted at rest with AES-GCM. No network. No telemetry. No analytics. No third-party SDKs.

---

## Why one more clipboard manager?

Most macOS clipboard managers either store history in plaintext, sync it to the cloud, or pull in a dependency graph wide enough to merit a security audit you'll never do. Clip-Board's posture is the inverse:

- **Encrypted at rest.** History is sealed with AES-GCM (256-bit) using a key stored in your Keychain (`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`, non-syncable). Deleting the Keychain entry irreversibly destroys the history — by design.
- **No network code in the binary.** Not "we promise" — there is no networking framework imported, no URLSession use, no analytics SDK.
- **Respects transient pasteboard markers.** Items written by password managers and other tools with `org.nspasteboard.TransientType`, `ConcealedType`, or `AutoGeneratedType` are skipped — never persisted.
- **Failure modes that don't lose data.** If decryption ever fails (corrupt file, key rotated externally), the file is quarantined to `history.broken-<timestamp>` instead of silently returning empty history.

---

## Features

- Global hotkey (configurable) to open a floating panel anywhere
- Menu-bar status item with right-click menu
- Pinned items + 100-item rolling window for the rest
- Auto-paste into the previously focused app via synthesized ⌘V (requires Accessibility permission)
- Fast keyboard navigation (↑ ↓ ⏎ ⎋)
- Debounced search with live filtering
- Multi-line text preserved exactly as copied
- Per-item size cap (100K chars) so a single huge copy doesn't bloat history
- Hotkey conflict detection: warns when you bind to a well-known macOS shortcut (⌘C, ⌘V, ⌘Space, etc.)

## Install

### Pre-built (recommended once releases are published)

Download `Clip-Board.app.zip` from the [Releases](https://github.com/SNGWN/Clip-Board/releases) page, unzip, drag into `/Applications`.

On first launch, macOS may show a Gatekeeper prompt because the binary is signed with a personal developer ID (or ad-hoc). If you've downloaded from the release page, right-click → Open the first time.

### From source

```bash
git clone https://github.com/SNGWN/Clip-Board.git
cd Clip-Board
open "Clip Board.xcodeproj"
```

In Xcode: select the `Clip Board` scheme, Product → Run.

Or from the command line (the build product lands at the project root):

```bash
./scripts/release.sh
```

## First run

1. App launches as a menu-bar item (no Dock icon — it's `LSUIElement`).
2. Right-click the menu-bar icon to see options.
3. Press `⌃⌥⌘V` (default) or click the menu-bar icon to open the history panel.
4. Auto-paste prompts for Accessibility permission on first use. Without it, items copy to the clipboard but won't auto-paste.

## Security model

### What Clip-Board protects against

- **At-rest disclosure.** Casual file inspection, backups uploaded to third-party services, or anyone with read access to your home directory can't read clipboard history without your Keychain key.
- **Cross-device leakage.** The encryption key is stored with `kSecAttrSynchronizable = false` — it does not propagate to iCloud Keychain or other devices.
- **Capture of sensitive transient data.** Password managers and similar tools mark pasteboard items as transient/concealed; Clip-Board honors these markers and skips them.

### What Clip-Board does not protect against

- An attacker with the same user privileges while the app is running (they can read decrypted history from memory).
- Loss of the Keychain key — the history file becomes permanently undecryptable. This is intentional: there's no recovery path or backup mechanism.
- Multi-user systems where another user has root-level access.

### Auto-paste and Accessibility

Auto-paste works by synthesizing a ⌘V keystroke into the previously focused app via `CGEvent`. This requires the system Accessibility permission. The code path is in [`AutoPaster.sendCmdV`](Clip Board/History.swift). If you deny the permission, items still land on the clipboard — you just paste manually with ⌘V.

## Architecture

```
┌────────────────────────────────────────────────────────────────┐
│                       Clip_BoardApp (@main)                    │
│  NSApplicationDelegateAdaptor → AppDelegate                    │
└────────────────────────────────────────────────────────────────┘
        │
        ├─ KeyManager           (Keychain, AES-GCM seal/open)
        ├─ PersistenceManager   (encode → encrypt → atomic write)
        ├─ ItemsViewModel       (dedupe, trim, pin, debounced save)
        ├─ ClipboardWatcher     (0.5s poll on changeCount, skips transient)
        ├─ HotkeyManager        (Carbon EventHotKey)
        ├─ AutoPaster           (NSWorkspace tracking + synthesized ⌘V)
        ├─ MenuBarController    (NSStatusItem + right-click NSMenu)
        └─ HistoryWindowController (cached NSPanel + NSHostingView)
```

The floating panel and the menu-bar window share the same SwiftUI root (`SharedHistoryRootView`). The panel is prewarmed off-screen at launch so the first user-visible show is instant.

---

## Data flow

1. User copies text → macOS pasteboard updates → `changeCount` increments.
2. `ClipboardWatcher` polls every 500ms, detects the change, filters transient types.
3. Trimmed text passed to `ItemsViewModel.addItem` — dedupe by exact equality (move-to-top) or insert new.
4. Debounced (300ms) save: encode JSON → AES-GCM encrypt → atomic write to `~/Library/Application Support/ClipboardManager/history.json.enc` (file mode 0600, directory mode 0700).
5. On launch: load file → decrypt → decode. If decrypt fails, quarantine and start fresh.

History is wrapped as `{ "version": 1, "items": [...] }` for forward compatibility. Legacy unversioned format is migrated transparently.

## Build & release

```bash
./scripts/release.sh           # Release build, ad-hoc signed, zipped
./scripts/release.sh --notarize # Same + submit to Apple notary service
```
